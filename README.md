## `> server_development`

### Multiplayer server engineering + plugin systems

I also build and operate **Minecraft server infrastructure and custom gameplay systems**. That work has taught me a different side of software engineering: real-time users, permissions, economy balance, cross-platform compatibility, deployment, uptime, debugging under pressure, and coordinating live releases.

```txt
SERVER WORK
────────────────────────────────────────────────────────
• Java + Bedrock cross-play infrastructure
• Geyser + Floodgate integration
• Permissions and rank architecture
• Economy + jobs + shop systems
• Team / guild-style systems
• Voice-chat integration
• Spawn protection and world-access rules
• Scoreboards, TAB formatting and role hierarchy
• Plugin configuration, extension and custom plugin work
• Live launch testing and production troubleshooting
```

### Plugin engineering

I create and customize plugin-driven systems around the needs of the server instead of installing plugins and leaving them at default settings.

```txt
PLAYER ACTION
     │
     ▼
┌───────────────┐
│ SERVER EVENT  │
└───────┬───────┘
        │
        ▼
┌────────────────────┐
│ PLUGIN / GAME LOGIC│
│ permissions        │
│ economy            │
│ teams              │
│ progression        │
│ moderation         │
└─────────┬──────────┘
          │
          ▼
┌────────────────────┐
│ PLAYER EXPERIENCE  │
│ feedback + state   │
└────────────────────┘
```

Some of the server tooling I work with includes **LuckPerms, Geyser, Floodgate, BetterTeams, Jobs, QuickShop, Simple Voice Chat, Pterodactyl, and VPS-hosted deployments**.

The main skill is not knowing a plugin name — it is understanding **how multiple plugins, permissions, data, network layers and player-facing rules interact as one production system**.
